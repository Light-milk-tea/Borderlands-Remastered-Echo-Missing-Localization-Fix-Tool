# 无主之地重制版 Echo 汉化丢失修复工具

在游玩无主之地1重制版的过程中，我发现 dlc 部分的 echo 对话没有汉化成功。  
我使用的是天邈最新版本的汉化包，BGOTYECNv1.0fix。  
我本来以为是汉化包没做这部分内容，但是经过了解，发现无主之地1原版反而可以成功汉化 dlc。  
于是我开始查找导致这个 bug 的根源。

先核对了天邈的文件，发现中文其实早就在 `Localization\INT` 的 `.int` 里了，并不是漏译。  
再对比原版和重制版同场景的资源，发现两边游戏读字幕的路径不一样。

原版里，地图上的本地化包（`*_LOC_INT.upk`，下文简称 LOC）里那些 echo 语音对象基本是“空壳”，几乎不带字幕正文。  
echo 播放时会回退到语音包（VO），再叠上天邈的 `.int`，所以中文能出来。

出问题的原因就在重制版这边。

可以简单理解成：游戏里同一句 echo，其实可能有两份“字幕稿”——  
一份在天邈的 `.int` 里（中文），另一份直接写在游戏资源包里（英文）。  
谁被优先读到，屏幕上就显示谁。

重制版为了切换英/日/德/法等语言方便，cook 资源时把各语言字幕写进了名叫 `LocalizedSubtitles` 的多语言槽里，并且塞进了地图 LOC；语音包（VO）里往往也留着同样一套槽。  
于是播 dlc echo 时，游戏常常先去读 LOC / VO 包里已经写好的英文字幕，根本轮不到再去合并天邈的 `.int`。

所以不是天邈没翻译，而是重制版“抄近路”读了包内英文。  
原版 LOC 几乎是空的，才会老老实实走 VO + `.int`，中文才能出来。  
（补充一句：主线其实也有 LOC 和 VO，并不是两套完全不同的系统；只是主线 echo 更常落到能被 `.int` 盖住的那条路上，dlc 则更容易先吃到包内英文。）

那么解决的办法也就来了：把重制版的 LOC 也弄成空的，echo 不就只能老老实实走老线路，经过天邈汉化了吗？  
方向是对的。不过实测里还有半截：如果 VO 里仍留着整套 `LocalizedSubtitles`，游戏有时还是会先吃包内英文，所以 VO 的多语言槽也要一并去掉，只留顶层 `Subtitles` 给 `.int` 覆盖。

中间也试过给 LOC 再挂 `.int`、改键名对齐加强版对象名，实测还是盖不住。  
也试过直接把中文灌进 upk，能出字，但改动大、维护重，而且一不小心还会弄坏音频偏移，出现无声、说到一半断掉、甚至进图不稳。  
这些弯路走完，最后还是回到上面说的“仿原版空壳”这条路上。

修复时具体做了三步：

1. 把 dlc 地图 LOC 里叙事用的 echo / 现场旁白对象空壳化，去掉包内的 `Subtitles` 和 `LocalizedSubtitles`，逼游戏回退到 VO  
2. 再把叙事 VO 里的 `LocalizedSubtitles` 多语言槽去掉，只保留顶层 `Subtitles` 和英文音频  
3. 这样天邈的 `.int` 就能重新覆盖 `Subtitles`，屏幕出中文，语音仍是英音  

过程中也踩过坑：如果把战斗喊话一类带内嵌音频的对象一起空壳，npc 会没声音；如果只削 echo、不管 `NAR_Live` 旁白，悬赏板那种小吵闹提示又会仍是英文；空壳后如果尾部还留着旧的大块音频指针，还可能出现说到一半声字幕没了、头像还在的情况。  
更麻烦的是：缩包之后，商店/广播一类没动到的短尾对象，也可能带着指向文件外的旧 Bulk 指针——浮空立交这类枢纽图一加载就会进不去。  
这些都在工具里按对象类型做了过滤，并且会对所有短尾脏 Bulk 做清洗，不只洗 echo。

本工具就是把上面这套流程做成一键操作。  
它不能代替天邈，必须先装好 BGOTYECNv1.0fix。  
一般用户不用自己装 Python：打开 `Echo_CN_Fix_Tool_Portable`，双击 `Echo_CN_Fix_Tool.exe` 即可。  
装完天邈后请完全退出游戏，再运行工具，选中游戏目录即可。  
具体步骤见同目录的 `使用说明.txt`。  
打完后不要点 Steam「验证游戏文件」，否则改动可能会被还原。

如果你也在重制版上遇到 dlc echo 明明装了汉化却仍是英文的问题，可以试试这个修复。

本人不是游戏汉化方面的大手子，只是运用 AI 去修复游玩过程中遇到的 bug。  
使用本工具前建议先备份，以免出问题。
